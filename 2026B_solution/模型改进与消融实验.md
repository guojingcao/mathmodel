## 2 未采用的改进

### 2.1 问题三：最小二乘试探清除的信任门限（`LS_CLEAR_GATE`）

诊断（300 例）：MEC 档（$\Omega\le20$m）首清 **100 %**；LS 档（$\Omega>20$m）**91.8 % / 89.6 %**，失败由归航补回。

| 门限 | 清除率 | Δ时间 | Δ移动 |
|---|---|---|---|
| 当前（LS 点直接盲清除） | 100 % | — | — |
| $\Omega\le40$m | 100 % | +24.6 s | +79 m |
| $\Omega\le30$m | 100 % | +421.5 s | +1 881 m |
| $\Omega\le25$m | 100 % | +892.9 s | +4 032 m |
| $\Omega\le20$m（仅 MEC） | 100 % | **+2 646 s** | +12 017 m |

**不采用**：单调劣化。拒绝盲清除要多付一次补测/归航，而盲试失败只损失 3 s 且由归航兜底。

### 2.2 问题四：补测距离上限（`SUPP_MAX_DIST`）

四臂配对（$n=400$×2，真配对）：各档 Δ 全部落在 **±10 s** 内，最大时间与长尾例数均无恶化，跳过仅 0.01–0.06 次/例。

**不采用**：无收益（早期"尾部最大值恶化 +444~+977 s"源于配对失效，已更正，见 §5）。
**机制结论**：距离可观测，但**不足以判断补测的信息价值**——阈值同时砍掉了"本可拿到第二条有效示向"的补测。

### 2.3 问题三：机会性顺带观测与补测点复用（模块 O / R，默认关）

利用"本来就要去的清除停靠点"做零移动观测（$\mathcal C_{opp}=\{\text{found}\wedge\text{未清除}\wedge(\Omega>20\text{m}\vee n<2\vee\alpha^{\ast}<30^\circ)\}$；先清除后观测，绝不返回已离开的点；`no_signal` 不裁剪可行域）。

| 档位 | 全案例 Δ [95 %CI] | 困难子集 | 复用尝试/例 | 删除任务/例 |
|---|---|---|---|---|
| O 规格口径 ≤1/≤2/≤3 | **+50.7 [41,60] / +83.9 [71,97] / +110.0 [95,125]** | +54 ~ +97 | 11–26 | — |
| **O 收紧口径 ≤2** | **−28.2 [−46,−11]** | **−51.1 [−84,−18]** | 5.2 | — |
| **R 双门控（认证或 LS 删）** | **−15.1 [−22,−8]** | **−28.3 [−42,−14]** | 0.85 | 0.14 |

（全档全清率 100 %；R 修复了"原补测任务触发归航后仍返回原点"的缺陷，额外成本 20.5 → 1.9 s/例。）

**默认关闭**：规格口径显著变差；两个正收益候选仅 0.3 % / 0.6 %，低于 0.5 %–1 % 采纳门槛。机制有效性待实现修复后重测（§5.3）。

### 2.4 策略审计门控：三项候选被"目标人群不存在"直接否决

实施前先用 `strategy_audit.py`（只测量、不改策略）确认待优化行为是否存在：

**P3 专用补测审计**（$n=200$，全清率 100 %）：补测 472 次（2.36 次/例），**收到示向 97.5 %**、`no_signal` 2.5 %、补测后仍未清除 **0 例**，补测阶段 526 s/例、**归航恢复仅 15.1 s/例（0.33 %）**。
→ "垂直补测几何差 → 补测无效 → 靠归航兜底"**不成立**；理论上的 $b\ge r\tan\alpha_0$、$r\le R\cos\alpha_0$（$r\le866$m）是最坏几何，实际极少触发。补测真实成本是**出行**（约 1 100 m/次），O/R 只能改善其中一小部分。

**P4 保证扫描审计**（$n=200$×2）：检测 521/553 次/例，其中**未发现频道的发现/证书测量占 41.1 % / 38.7 %**（214 次/例，硬保证成本）；**已认证后仍被测量 0.00 次/例**；**换频实际 = 最少（487/487、518/518，可省 0 s）**。
→ 拟定的两个候选（认证后停止测量、换频顺序优化）**已实现或已最优**。证书成本只能靠**减少顶点数**间接降低——这正是网格改进同时减少 90 次检测/例的原因。

## 5 实验口径勘误（重要）

### 5.1 逐案例"配对"曾失效

**根因**：`exp.Env` 用同一随机源既生成场景、又在每次 `measure` 抽 ±1° 噪声；各臂测量次数不同就错开随机流 ⇒ **同一编号在不同臂下是不同场景**，逐案例配对与"困难子集"划分全部失效，置信区间被放大一个数量级。
**修复**：场景随机源按 $(\text{seed},\text{案例编号})$ 独立派生，逐案例落盘 `scene_hash` 核对；`ablation3.py --order-test` 验证"独立跑 / 前置其他实验 / 打乱顺序"逐案例一致。
注意：修复保证**同场景**，不保证**同噪声**——"置信区间变窄"不等于配对正确。

### 5.2 审计脚本 `audit.py` 的口径与实现更正

| 项目 | 原（错） | **更正后** |
|---|---|---|
| 三个"下界" | `LB0/LB1/LB2`，称"架构损失已精确量化" | `UB_center`（访问源中心 = **上界**）、`REF_separated`、`REF_fused`；新增**严格下界** `LOWER_disk = UB_center − 2nR_clear` |
| 开放路径 2-opt | 固定终点（缺 $j=n$ 尾段反转），仅 `audit.py` 有此问题 | 已修；**正式程序无此问题** |
| 精确解降级 | $n>14$ 静默用启发式冒充精确解 | 显式标记 `exact=False` |
| 扫描结束距离 | `n_measure==140` 触发（冻结版几乎不命中），第 0 覆盖点是原点会记成 0 | 改由**阶段表真值**给出，并加分账一致性自检（偏差 0.000 m） |
| 清除核验 | 无 | 三方一致：机器人返回 = 客户端成功数 = `env.cleared` = 源数 |
| G_info | 9 898 m | **2 409 m** |
| 2-opt vs 精确 | 2.03 %（中位 0 %） | **均值 3.02 %、中位 0.05 %、最大 15.91 %**（24/30 例可精确） |

**结论层**：撤回"架构已接近绝对上限"——只能说"在既定 7 点骨架与分阶段参考口径下，ALG 相对 `REF_separated` +13.3 %、`REF_fused` 相对 `REF_separated` 改善 33.8 %"。**保持冻结是工程决策，不等于证明全局最优。**

### 5.3 共享库与待办

`simlib.py`：唯一计时口径（移动/5+检测×5+换频×1+成功清除×5+失败清除×3）＋阶段时间含换频与清除＋逐动作账本自检；清除率区分"案例全清率 / 平均源清除比例 / 漏清源数"；每臂 = **完整冻结配置 + 覆盖项**，`config_scope` 退出无条件恢复；统计对空集/单例安全，稀疏模块用成对 bootstrap 区间。
**待办**：模块 O 的成本累计（`snap0` 在循环外导致重复计时）、执行前状态复核、机会观测后更新待执行清除坐标、R"不触发时与基线等价"测试——不改策略，但**引用 O/R 机制结论前必须完成**。

## 7 小结

1. **结构冻结**：两问的覆盖、定位、证书、调度结构不再改动；阈值类候选（LS 门限、补测上限、$\delta$、邻域、机会观测、补测复用）经真配对**全部否决或维持原值**。
2. **唯一采纳的性能改动**是问题四网格几何（离线 −9 %、实机 −11.6 %，P90/最大同步改善，正确性指标不变）。
3. **四条教训**：① 可观测的量（$\Omega$ 半径、补测距离、空闲停靠点）不等于决策所需的信息；② 先检查"目标人群是否存在"（审计门控），再谈优化；③ 同场景配对必须隔离场景随机源，"置信区间变窄"不能当作配对正确的证明；④ 跨批次总时间不可比——用固定成本或按源归一。
4. **小样本 100 % 不能替代正确性检验**：证书索引缺陷只在扩大样本 + 逐动作核对后才暴露。
